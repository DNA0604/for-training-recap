# Audit UI: jarak, tombol tutup dan filter Peserta

Tanggal: **4 November 2026, Asia/Jakarta**. Sumber yang diperiksa: `96671c9` pada `perf/pemeriksaan-pemuatan-data`. Pengguna menegaskan **“Audit dan rancangan perbaikan dahulu”**. Dokumen ini mencatat temuan/rancangan; belum menerapkan perubahan kode, CSS, data atau deployment. Penerimaan nilai akhir tetap berlaku; hasil waktu pemuatan setelah paket sebelumnya masih belum dilaporkan pengguna.

## Lingkup dan cara pemeriksaan

Diperiksa: Beranda, Monitoring, Pengelolaan, Peserta Program, Profil Peserta dan Manajemen Akses; termasuk dialog yang dibuat dinamis oleh Akses.gs/Evaluasi.gs. Pembacaan markup/CSS/handler dilengkapi pengukuran Chromium pada lebar **1361 px** dan **390 px**, menggunakan HTML asli yang diinjeksi server serta akun/data Google tiruan. Pengukuran bukan pembacaan deployment Google pengguna. Panel native pemilik di spreadsheet dan halaman QR publik tidak menjadi cakupan utama audit ini.

Ada 33 **kemunculan dialog** pada enam halaman Admin yang dirender: 1 Beranda, 19 Monitoring, 8 Pengelolaan, 4 Peserta, 1 Profil dan 0 Manajemen Akses. Beberapa dialog yang sama muncul di lebih dari satu halaman. Sembilan kemunculan memiliki ikon X; 24 lainnya memakai Tutup/Batal tanpa X. Ini bukan berarti dialog tersebut sama sekali tidak dapat ditutup. Tidak ada error JavaScript pada render sampel desktop/ponsel.

## Standar tampilan yang diusulkan

- **12 px** untuk jarak antartombol/tindakan dan antarcard yang merupakan satu kelompok. Card yang menempel mendapat prioritas. Jarak internal ikon–teks, padding card, pemisahan antarbab halaman dan sidebar tidak disamakan secara membabi buta; itu memiliki fungsi berbeda.
- X memakai tombol **44 × 44 px**, ikon **20 px**, sudut sekitar **12 px**, warna/border navy yang mengikuti tampilan sekarang. Tetap di kanan atas saat judul panjang membungkus pada ponsel; bukan ikut turun ke bawah judul.
- Header/jalur tutup tetap mudah dijangkau pada modal panjang. Modal evaluasi yang sudah memiliki scroll tabel terpisah dan header tetap dipertahankan.
- X harus memiliki label aksesibel, misalnya “Tutup presensi manual”, fokus keyboard yang terlihat dan `type="button"` agar tidak mengirim form.
- Tombol X dan Escape mengikuti handler penutupan yang sama dengan Tutup/Batal saat ini. Saat proses simpan/unggah/hapus belum selesai, penguncian tetap berlaku. Peringatan isian belum tersimpan dan ID percobaan ulang tetap dijaga. X pada konfirmasi hapus setara **Batal**, tidak menjalankan penghapusan.
- Tab yang memang menjadi satu kontrol tersegmentasi tidak otomatis diberi gap 12 px. Animasi/sidebar dan aturan otorisasi tidak termasuk redesign.

## Rancangan khusus Program → Jenjang pada Peserta

1. Card menampilkan **Program Tujuan**, keterangannya, lalu **Jenjang Tujuan / Filter Peserta** di bawahnya.
2. Program kosong: Jenjang kosong dan nonaktif, dengan petunjuk memilih Program. Berlaku pula ketika Program dikosongkan kembali.
3. Program dengan satu Jenjang: Jenjang aktif dan terpilih otomatis sebagaimana perilaku sekarang.
4. Program dengan beberapa Jenjang: pilihan mengikuti Program; tampilan “Semua Jenjang (lihat)” tetap untuk membaca daftar, sedangkan penambahan/impor tetap mensyaratkan satu Jenjang tujuan.
5. Saat Program berubah, hapus pilihan Jenjang lama sebelum mengisi pilihan baru; jangan membawa pilihan dari Program sebelumnya.
6. Penguncian selama simpan/impor serta pembatasan Jenjang untuk Petugas/Pengajar tetap dijaga. Ini perbaikan urutan dan keadaan kontrol, tanpa pemindahan peserta atau migrasi data.

## Pemeriksaan setelah implementasi nanti

Ukur jarak dan X pada desktop/ponsel; coba judul panjang, tombol yang membungkus, modal panjang, klik X/Escape, keadaan proses sedang berjalan, serta isian belum tersimpan. Pastikan membuka/menutup modal tidak menulis data. Uji Program kosong → satu Jenjang → beberapa Jenjang → ganti/kosongkan Program, lalu pastikan pilihan dan hak akses tetap sesuai. Tidak ada klaim bahwa pemeriksaan perilaku ini sudah dijalankan pada kode perbaikan: implementasinya memang belum dibuat.
